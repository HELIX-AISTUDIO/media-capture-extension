## 1. 设计约束（未来开发必须遵守，保证不污染现有逻辑）

### 1.1–1.5 原有约束（沿用，不变）

1. 旁路是一条**独立通道**，只在"当前页命中解析站点表"时出现，与 webRequest 抓取结果解耦。
2. 新增消息 action 用**新 case**，不改 `getResources / download / sendToAria2 / parseM3u8 / parseMpd` 等任何既有 case。
3. 站点判定收敛在独立文件 `site-resolver.js`（一张表），未来加站点只改这张表。
4. 引擎可切换：`mode = 'helper' | 'gd3'`，方案 1/方案 2 共用同一段扩展代码。
5. YouTube 页面抓到的 googlevideo 临时链默认**不展示/置后**，避免用户误下无声或被限速单流。

### 1.6 🆕 i18n 国际化约束（v0.3.3 引入，V2.0 必须遵守）

v0.3.3 起项目有完整 i18n（`zh_CN` 默认 + `en`，各 **223 条** key，两边必须一致）：

| 要求 | 做法 |
| --- | --- |
| HTML 元素 | 加 `data-i18n` / `data-i18n-title` / `data-i18n-placeholder`，并**保留中文原文作兜底**（如 `<button data-i18n="rs_download">解析下载本页</button>`） |
| JS 文案 | 用 `t('key', '中文原文')`，带变量用第三参 `t('key','已入队 $1 个…',[n])` |
| 语言包 | `_locales/zh_CN/messages.json` 与 `_locales/en/messages.json` **同步补 key**，保持 223→N 两边相等 |
| 富文本 | 含内联标签用 `data-i18n-html`（`js/i18n.js:107` `localizeHtml`） |

> **⚠️ 已发生的反面教材**：`popup.html:20` 的「流媒体」标签写了 `data-i18n="popup_filter_stream"`，
> 但 **zh_CN 与 en 两个语言包都没有这个 key**（grep 实测 0 命中）→ 中文靠"原文兜底"显示正常，
> **英文界面会漏出中文**。V2.0 新增任何 UI **必须同时补 key**，不能只靠兜底。

### 1.7 🆕 DNR 用途分账约束（v0.3.2 BUG-1 的教训，V2.0 必须遵守）

若 V2.0 新增任何**下载 / 预览**路径并要注入 Referer/Cookie/Origin：

- 调用 `setPreviewRefererRule(url, headers, purpose)`（`js/background.js:659`）时，**`purpose` 必须显式传 `'download'` 或 `'preview'`**；
- 不传会落到默认值 `'preview'`（`js/background.js:665`），可能被"下载结束清理"误删 → 正在预览的防盗链资源突然 403（**这是踩过的坑**）；
- 结束后用 `releaseRule(url, purpose)`（`js/background.js:758`）**精确释放**该资源，或 `clearDownloadRules()` / `clearPreviewRefererRule()` 按用途清理；
- 只注入 forbidden 头（`referer/cookie/origin`，见 `DNR_FORBIDDEN_HEADERS`，`js/background.js:646`）；`authorization` / `x-*` 由 viewer 的 fetch 直接携带，不走 DNR。

> 记忆点：**清理动作的作用域必须等于它真正拥有的资源范围**（详见 `docs/LEARNINGS.md` v0.3.2 节）。

### 1.8 🆕 嗅探总开关与旁路的联动（v0.3.3 引入，结论在此定死）

**结论：暂停嗅探时，「解析本页」卡片照常显示且可用，不受影响。**

理由（代码事实）：

1. `captureEnabled` 只做三处早退，全部是**网络捕获**入口：`onBeforeRequest`（`js/background.js:1067`）、`onSendHeaders`（`:1090`）、`onResponseStarted`（`:1135`）；
2. 内容脚本扫描也被停（`sniffPaused`），但这两者都只影响"**新资源的采集**"；
3. **`getResources`（读取列表）与 `addDomResources`（DOM 上报，`:1644`）都没有 `captureEnabled` 判断**——已抓到的列表照常可读；
4. 旁路的唯一输入是 `currentTabUrl`（`js/popup.js:873`，在 `refresh()` 里**无条件**赋值），**不依赖任何捕获结果**。

因此定义：**暂停 = 暂停"采集新资源"，不暂停"已抓列表的读取/下载"，也不暂停旁路解析。**

- 旁路卡片**不要**跟着暂停隐藏——否则用户暂停后进入 YouTube 会以为功能坏了；
- 若将来产品要求 "暂停时隐藏旁路"，唯一改动点：`js/popup.js:46` `applySniffSwitchUI()` 内加一行调用 `renderResolverCard()`（或 `box.style.display='none'`），**不要在旁路代码里再读一次开关状态**。

### 1.9 🆕 弹窗按钮排布（v0.3.3 已占用 6 个按钮）

`popup.html:23–30` 的 `.actions` 内现已有 6 个按钮：**刷新 / 清空 / 设置 / 自动下载 / 导出 / 录制**。

- `.actions` 已有 `flex-wrap: wrap`（`css/popup.css:87`，注释即为"新增录制按钮后允许换行"），**再加按钮不会破版**；
- 但 V2.0 的「解析本页」**建议不作为第 7 个工具栏按钮**，而是走 §3.4 的**条件卡片**（默认 `display:none`，仅命中站点才显示）——普通站点用户零感知，符合 §1.1「独立通道、解耦」原则；
- 若最终决定放按钮：插在 `popup.html:23–30` 内、`.actions` 中，**并同步补 i18n key**（§1.6）。

### 3.2 配置变量与热更新（接入点 2/3/4，沿用现有 aria2Rpc 模式）

let ytHelperUrl = '';     // 方案1 本地助手地址 http://127.0.0.1:17890

### 3.3 新消息分支（接入点 5，核心）
- 在 `safeOn(chrome.runtime, 'onMessage', …)`（**第 1337 行**）的 `switch(msg.action)`（**第 1340 行**）内，
  找到 `case 'sendToAria2'`（**第 1541 行**）整块结束（**`return true;` 第 1577 行 / `}` 第 1578 行**）之后，
  **平级**插入 `case 'resolvePage'` —— 即插在 **1578 之后、下一 case `case 'download'`（第 1580 行）之前**。
- 该分支职责：规整 URL → 校验命中站点表 →（可选）用 `chrome.cookies.getAll` 取登录 Cookie →
  按 `mode` 走 gd3（复用 `aria2Rpc` 发 `aria2.addUri`，uri 用**页面 URL**）或 helper（POST 本地助手 `/download`）。
- 异步响应 `return true;`，与现有异步 case 风格一致。**完整代码见 03 文档第 2.5 节。**
- 该分支**不受 `captureEnabled` 影响**（与 `getResources` 一致，见约束⑧）。

### 3.4 popup 卡片（接入点 6/7/8/13）
- popup.html 在 `popup.js` 之前引入 site-resolver（第 63–64 行之间）；在 `<main id="list">`（**第 55 行**）上方放默认隐藏卡片。
- **i18n（约束⑥）**：卡片内所有可见文案都要 `data-i18n` + 中文原文兜底，并在两个语言包补 key（03 文档 §3.1 已给出带 i18n 属性的版本）。
- popup.js 已有全局 `currentTabId / currentTabUrl / currentTabTitle`（`refresh(isRetry)` 第 872–874 行赋值），旁路直接复用，不必再查 tab。
- **调用点建议**：放在 `function render()`（**第 295 行**）末尾，而不是只放在 `refresh()` 的回调里——
  因为 v0.3.3 起 `refresh(isRetry)` 有"空列表 300ms 后重试一次"的逻辑（`scheduleEmptyRetry`，**第 862–866 行**），
  重试也会走 `render()`（887/897 行），放在 render 末尾可覆盖首次 + 重试两条路径。
- `renderResolverCard()`：`SiteResolver.match(currentTabUrl)` 命中才显示卡片，否则隐藏——普通站点用户完全感知不到这条旁路。
- 方案1 用 `setInterval` 轮询 `/status` 显示百分比；popup 关闭轮询即停，**不影响本地下载继续**。

### 3.5 权限（接入点 10）
- 读 `tab.url`、向 `http://127.0.0.1` 发 fetch：现有 `<all_urls>` host 权限已覆盖，**不用加**。
- 仅当要自动带 YouTube 登录 Cookie（私密/会员/年龄视频）时，`permissions`（第 10–21 行）增加 `"cookies"`；
  代码里对 `chrome.cookies` 做存在性判断，没授权就降级为不带 Cookie（公开视频照常）。

## 8. 风险与注意事项（未来开发时回看）

- **必须有本地进程**：纯扩展无法下 YouTube（MSE/签名/无 ffmpeg/SW 休眠），这是硬边界，不要再尝试纯扩展方案。
- **yt-dlp 需保持更新**：YouTube 改版会让旧版解析失败，助手要支持一键替换 exe / `yt-dlp -U`。
- **登录态/地区**：私密、会员、年龄限制靠 Cookie；地区不可用靠代理（助手支持 `--proxy`）。
- **本地端口安全**：助手只绑 127.0.0.1，并建议设 `HELPER_TOKEN`（请求头 `x-helper-token`），防止任意网页调本机。
- **商店合规**：扩展本身不内置下载受版权保护内容的能力、不内置二进制；只做"把 URL 交给用户本机运行的程序"，
  与现有 aria2 推送性质一致，合规风险可控（发布前再核对商店政策与本项目 PRIVACY/COMPLIANCE）。
- 🆕 **i18n 漏 key**：只加 `data-i18n` 不补 key，中文看不出来、英文直接漏中文（v0.3.3 的 `popup_filter_stream`
  已踩过）。发版前必须做一次"key 数相等 + 全量页面无中文漏出"检查。
- 🆕 **DNR purpose 漏传**：默认 `'preview'`，会被下载清理误删导致预览 403（v0.3.2 BUG-1）。新路径务必显式传参。
- 🆕 **暂停开关语义**：不要把旁路或"已抓列表的下载"也一起暂停——暂停只停"新资源采集"（约束⑧），
  否则用户会以为扩展坏了。
- 🆕 **行号锚点漂移**：本文件行号基于 v0.3.3。**永远以"代码特征"为准**；特征搜不到时标注
  "该特征已不存在，需重新定位"，**不要编造行号**。
