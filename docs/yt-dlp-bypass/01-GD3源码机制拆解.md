# 01 · Ghost-Downloader-3 源码机制拆解（对照版本：桌面 v4.3.5 / 扩展 v2.2.0）

> 目的：把"GD3 凭什么能下 YouTube、各模块怎么协作"讲清楚，并标注**哪些设计可迁移到本项目、哪些受
> MV3 限制不能照搬**。所有路径均相对于 `Ghost-Downloader-3-main/`。

---

## 1. 总体：一个"双进程"系统，不是一个浏览器扩展

```
┌─────────────────────────── 浏览器扩展（TS + WXT + React，MV3）──────────────────────────┐
│ webRequest 抓媒体 + 请求头快照；content script(MAIN world) 钩 MSE；                        │
│ 只负责"发现资源 / 遥控"，自身不下载字节                                                    │
└───────────────┬───────────────────────────────────────────────────────────────────────┘
                │  ① WebSocket 127.0.0.1 + token（browser_service）
                │  ② aria2 兼容 JSON-RPC 127.0.0.1:16800（aria2_rpc，默认关闭）
                ▼
┌─────────────────────────────── 桌面宿主（Python 3.13 + PySide6 + asyncio）──────────────┐
│ FeatureService 按 URL/类型路由 → 命中某个 FeaturePack → pack.parse() 生成 Task             │
│ TaskService 队列/并发/持久化 → Task 内多个 TaskStep 依次 run() → 真正下载/合并             │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

顶层入口 `Ghost-Downloader-3.py` → `app/startup.py` 装配容器 `app/container.py`。

### 顶层目录职责
- `app/`：宿主框架（与具体协议无关）。`loader.py` 装载插件、`services/` 放各服务、`models/` 放数据模型、
  `client.py` 是带 TLS 指纹伪装的 HTTP 客户端（基于 wreq，可模拟 chrome/safari/edge 指纹）。
- `features/*_pack/`：**垂直功能插件包**，每个下载协议/站点一个目录，互相独立、可单独禁用。
- `browser_extension/`：配套浏览器扩展源码。
- `runtime/`、各 pack 内 `BinaryRuntime`：外部二进制（ffmpeg、N_m3u8DL-RE、yt-dlp、qjs、aria2c 等）。

## 2. 插件化机制：FeaturePack（未来本项目"引擎侧"最值得照搬的骨架）

### 2.1 装载：`app/loader.py`
- 扫描 `features/*/manifest.toml`，每个包含 `entry`(入口文件)、`class`(Pack 类名)、`dependencies`(依赖的其他 pack)、版本、最低宿主版本。
- 逐包导入，**单个包导入/初始化失败只禁用该包并记录，绝不拖垮整个宿主**——这是"可插拔"的关键健壮性。

### 2.2 路由：`app/services/feature_service.py`
- 每个 Pack 暴露若干 `TaskParser`，parser 有 `priority` 与 `match(options)`。
- 收到任务（URL）时按优先级找第一个 `match()` 命中的 parser，调 `await parser.parse(options)` 得到 `Task`。
- **YouTube 的命中条件是"页面 URL 的域名"**，不是媒体类型（见 §4）。

### 2.3 基类：`app/models/pack.py`
- `FeaturePack`：声明 `packId`、`parsers`、可选 `runtimes()`（依赖哪些外部二进制）、设置卡片、任务卡片。
- `TaskParser`：`match()` + `parse()`。
- `BinaryRuntime`：统一描述一个外部可执行文件（安装目录、探测路径、版本、在线安装）。

### 2.4 任务模型：`app/models/task.py`
- `Task` 含一组有序 `TaskStep`；状态机 `WAITING / RUNNING / PAUSED / COMPLETED / FAILED`。
- Task 聚合各 step 的 progress/speed/receivedBytes；可序列化为 jsonl。
- `TaskStep.run(reportSpeed, waitForSpeedLimit)` 是最小执行单元；子类实现具体下载/合并动作。

### 2.5 调度：`app/services/task_service.py`
- `TaskQueue`（waiting 列表 + running 表）+ `_pump()`：运行数 < `maxTaskNum` 就取下一个派发。
- `TaskStore` 把任务**追加/全量写到 `tasks.jsonl`**，重启后 `resumeSaved()` 恢复（崩溃续传的上层部分）。
- 支持暂停/继续/重下/改选项/文件去重/磁盘空间检查/输出文件被移动的监听。

> **可迁移**：未来本项目的"本地助手"即使很薄，也建议照这个"路由 → handler(pack) → task/steps →
> 队列 → 持久化"分层，先只做 http 与 yt-dlp 两个 handler，后续加站点不动主干。
> **不照搬**：PySide6 GUI、TLS 指纹库等对"下载 YouTube"非必需，v1 全部不需要。

## 3. 普通 HTTP 下载是怎么做的（`features/http_pack/`，理解对比即可）

- `pack.py`：发 HEAD/Range 探测，判断 `Content-Length` 与 `Accept-Ranges`，决定是否支持多线程与断点。
- `task.py`：把文件按字节区间切成 N 块，**N 个 subworker 并发用 `Range: bytes=a-b` 拉取**，
  预分配文件并按偏移 seek 写入；用 `.ghd` sidecar 记录已收字节实现暂停后续传；不支持 Range 的源回退单流。
- m3u8/dash_pack 则是**封装外部二进制 N_m3u8DL-RE + ffmpeg**（拼命令行、解析 stdout 进度）。

> 这解释了 GD3 的两种"重活"外包方式：**HTTP 自己写多线程**；**流媒体/站点解析交给专业外部二进制**。
> YouTube 属于后者（yt-dlp）。

## 4. 重点：`features/yt_dlp_pack/` 是怎么下 YouTube 的

### 4.1 `manifest.toml`
```toml
[pack]
entry = "pack.py"
class = "YouTubePack"
dependencies = ["http_pack", "ffmpeg_pack"]   # 复用 HTTP 下载步与 ffmpeg 合并步
```

### 4.2 `pack.py`：按域名命中，输入是"页面 URL"
```python
YOUTUBE_HOSTS = ("youtube.com", "youtu.be")
class YouTubeParser(TaskParser):
    priority = 70
    def match(self, options):
        host = (urlparse(options.url).hostname or "").lower()
        return any(host == h or host.endswith(f".{h}") for h in YOUTUBE_HOSTS)
    async def parse(self, options):
        # 1) 若扩展带了 Cookie，且含登录态字段则落盘备用（私密/会员/年龄）
        # 2) 用 youtube.com/oembed 拿标题（失败兜底"YouTube 视频"）
        # 3) 生成 YouTubeTask，挂一组 Step
```
**关键：`options.url` 是 `https://www.youtube.com/watch?v=...` 这种页面地址，不是 googlevideo 媒体地址。**

### 4.3 `config.py`：运行时与 Cookie
- `YouTubeRuntime(BinaryRuntime)`：name=`yt-dlp`，随宿主安装 **yt-dlp（nightly）+ QuickJS(qjs)**。
  - 之所以要 qjs：GD3 把 `yt_dlp` 当 **Python 库 import**（见 task.py `importlib.import_module("yt_dlp")`），
    库本身不带 JS 引擎，需要外部 QuickJS 执行 YouTube player JS 来解 n 签名。
  - **对比：官方独立 `yt-dlp.exe` 自带 JS 解释器，不需要额外 qjs**——本项目方案 1 用 exe 可省掉这一层。
- Cookie：`saveCookiesIfBetter()` 只在 Cookie 含 `LOGIN_INFO/SAPISID/__Secure-*PAPISID` 等登录字段时
  存成 Netscape `cookies.txt`。

### 4.4 `task.py`：一个视频 = 5 个 Step（这是"页面解析→成片"的完整流水线）
`buildStepGroup()` 为每个视频生成：

| 顺序 | Step 类 | 职责 |
| --- | --- | --- |
| 1 | `YouTubeExtractStep` | **只解析不下载**：`yt_dlp.YoutubeDL(opts).extract_info(url, download=False)` 拿到全部 formats；`buildFormatPair()` 选出最佳**纯视频** format 与最佳**纯音频** format，把它们的真实直链 `fmt["url"]`、`http_headers`、体积回填给后续步骤 |
| 2 | `YouTubeResourceStep(role=video)` | 继承 ffmpeg_pack 的资源步 / http_pack 的多线程下载，下载**纯视频**流（Range 分片） |
| 3 | `YouTubeResourceStep(role=audio)` | 同样方式下载**纯音频**流；可按语言选多音轨 |
| 4 | `YouTubeMergeStep` | 调 **ffmpeg** 把视频+音频**合并/重封装为 mp4**（`-c copy`），可选写入标题/作者/章节元数据、按时间切片 |
| 5 | `YouTubeSubtitleStep` | 可选下载字幕 vtt；另有 `YouTubeCoverStep` 下载封面 |

- 选格式 `buildFormatPair()`：只取 `protocol in {http,https}` 的直连格式，视频按 height/码率排序、
  音频按 abr/语言排序，支持"优先 mp4、限最高清晰度、限最高音频码率、多音轨语言"。
- 播放列表：`probePlaylist(extract_flat=True)` 先平铺出每个视频 id，再为每个视频生成同一组 Step。
- 错误翻译 `ERROR_HINTS`：把 yt-dlp 常见报错（地区不可用/私密/会员/年龄/人机验证/403）映射成中文引导，
  并统一提示"可通过浏览器扩展下载以携带登录 Cookie"。**这套错误文案未来可直接借鉴。**

> **本质**：yt-dlp 负责"逆向 + 解密 + 给出带签名的真实直链"，下载与合并仍走 GD3 自己的引擎/ffmpeg。
> 本项目方案 1 的简化版是让 `yt-dlp.exe` 一步到位（自己下载+调 ffmpeg 合并），先求可用；
> 将来要多线程提速/精细续传，再升级成"extract_info 只取直链 → 自下载 → ffmpeg 合并"的 GD3 模式。

## 5. 桌面端的两个对外"接任务"入口

### 5.1 `app/services/browser_service.py`：WebSocket（配套扩展主用）
- 在 127.0.0.1 起 WS 服务，扩展连接后先发 token 握手，随后双向收发：扩展下发 `create_task`，
  桌面回推任务状态（扩展刷角标/列表）。免注册表、跨浏览器、可双向，是 GD3 的主通道。

### 5.2 `app/services/aria2_rpc.py`：aria2 兼容 JSON-RPC（本项目方案 2 的关键）
- 在 127.0.0.1:`cfg.aria2RpcPort`（**默认 16800，`isAria2RpcEnabled` 默认 False 需手动开**）起一个
  极简 HTTP 服务，**让任何会说 aria2 协议的客户端/扩展都能把任务塞给 GD3**。
- 仅实现两个方法：`aria2.getVersion`、`aria2.addUri`。
- token：若设置了，`params[0]` 必须是 `"token:xxx"`。
- `aria2.addUri` 的入参与转换（和标准 aria2 一致）：
  - `params = [token?, [url], options]`
  - options 支持：`out`(文件名)、`dir`(目录)、`header`(字符串数组，形如 `"Cookie: xxx"`)、
    `user-agent`、`referer`。
  - 它把这些组装成内部 `TaskOptions`，**调用统一的 parse 管线**——于是传 YouTube 页面 URL 就会被
    路由到 `YouTubeParser`/yt-dlp。这就是"本项目现有 sendToAria2 几乎零改造就能驱动 GD3 下 YouTube"的根据。

> 注意：GD3 设置里若开启"任务先建草稿(draft)"，RPC 进来的任务会先在 GUI 等确认，不会自动开始。

## 6. 配套浏览器扩展侧：捕获 vs "external 页面下发"

扩展源码在 `browser_extension/app/src/`：

- `background/resource-bridge.ts` + `resource-cache.ts`：用 `chrome.webRequest`
  （onSendHeaders/onHeadersReceived/onCompleted…）缓存资源与**请求头快照**（含 Cookie/Referer/UA）。
- `background/desktop-bridge.ts`：WS 客户端，负责连接/握手/发送/收状态/角标。
- **YouTube 专门策略** `page-media/resolution/strategies/youtube.ts`（全文）：
  ```ts
  // YouTube's media URLs are SABR/cipher-gated and not re-downloadable,
  // so we delegate the page URL to the desktop's yt-dlp and ignore captured URLs.
  export function selectYouTube(ctx) {
    return { kind: "selection", selection: { kind: "external", pageUrl: ctx.pageUrl.href } };
  }
  ```
- `background/resource-bridge.ts` 的 `downloadPageMedia()` 对 `selection.kind === "external"` 走
  `sendExternalDownload()`：
  ```ts
  sendDesktopRequest({
    type: "create_task", source: "page_media",
    payload: { url: selection.pageUrl,            // ★ 页面 URL，不是媒体 URL
               pageUrl, pageTitle: title,
               headers: cache.headersForPage(selection.pageUrl) } // ★ 带登录 Cookie
  }, 120_000)
  ```

**这就是"旁路"在扩展侧的标准形态：一个站点策略返回 external/pageUrl，下发时带当前页请求头。**
本项目未来的 `site-resolver.js` + `resolvePage` 分支就是对它的等价实现（更简化）。

## 7. 对本项目：可迁移 vs 不可照搬清单

### 可迁移（建议吸收）
- **双范式并存、页面 URL 驱动**的思路与"external 选择器"模式。
- **aria2 兼容入口**：本项目已有 aria2 客户端，未来方案 2 直接复用；方案 1 的本地助手也可实现同样的
  `aria2.addUri`，让两套引擎可互换。
- **yt-dlp 五步流水线心智模型**（解析选格式 → 下视频 → 下音频 → ffmpeg 合并 → 字幕/封面），方案 1
  先用 exe 一步到位，后续按此分步升级。
- **Cookie 透传**（登录态视频）与**错误中文化映射**。
- **插件化分层**（路由/handler/task-step/队列/持久化），保证后续加站点不动主干。

### 不可照搬 / 不必做
- 不在扩展里实现 yt-dlp 的签名解密（持续对抗、需 JS 运行时，直接用 yt-dlp 上游成果）。
- 不在扩展里用 ffmpeg.wasm 合并（体积/内存/SW 生命周期均不允许，已有定论）。
- v1 不需要 PySide6 GUI、TLS 指纹库(wreq)、libtorrent/aioftp 等与"YouTube 下载"无关的重型组件。
- 不需要 QuickJS：方案 1 用官方 `yt-dlp.exe`（自带 JS 解释器）。
