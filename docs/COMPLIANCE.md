# 法律合规风险校验（COMPLIANCE）

> 本文档记录 Media Catch（媒体抓取器）项目的法律合规校验结论、法条依据与不可逾越的边界红线。
> 用途：新会话/新协作者快速了解项目合规状态；商店上架审核前自查依据。
> 最近校验：2026-09-09

---

## 一、校验结论（摘要）

**当前项目状态：作者（开发者）个人被追责的法律风险很低。** 核心原因：
1. 项目是**通用媒体嗅探工具**（类似浏览器开发者工具/下载管理器），不属于"专门用于侵权"的工具；
2. 代码层面**不解析加密流、不绕过 DRM/防盗链**，直接排除《著作权法》第53条第6项规制情形；
3. MIT License 免责条款 + README/PRIVACY 合规声明，构成免责与证据基础。

**实际最高风险不是个人法律责任，而是"项目被版权投诉下架"（影响项目存续），可用声明 + 及时响应投诉管控。**

## 二、法律依据（已核实条款）

### 1. 《民法典》第1169条 —— 帮助/教唆侵权连带责任
> 教唆、帮助他人实施侵权行为的，应当与行为人承担连带责任。
- **意义**：判断"作者是否要为使用者行为担责"的核心条款。构成要件 = **明知 + 提供实质性帮助**。

### 2. 《著作权法》第53条第6项 —— 技术保护措施红线
> 未经著作权人许可，**故意避开或者破坏技术措施**，**故意制造、进口或者向他人提供主要用于避开、破坏技术措施的装置或者部件**，或者**故意为他人避开或者破坏技术措施提供技术服务**——属侵权行为。

### 3. 两高《关于办理侵犯知识产权刑事案件适用法律若干问题的解释》（法释〔2025〕5号）第13条
> **明知**他人实施侵犯著作权犯罪，仍提供主要用于避开、破坏技术措施的装置/部件，或提供技术服务，达数额标准 → 以侵犯著作权罪追究刑事责任。
- **意义**：红线行为可能从民事侵权升级为刑事风险。

## 四、三层保护（为什么基本不影响开发者）

1. **工具中立性**：通用媒体嗅探工具，法律上属"双重用途工具"，不因他人拿来侵权而当然归责；
2. **代码无规避功能**：不碰 DRM/加密/防盗链 → 排除著作权法53条与两高解释要件，**最强护城河**；
3. **MIT + 声明**：MIT"按现状提供、不承担保证责任" + README/PRIVACY 合规声明。

> ⚠️ 注意：**MIT 免责条款不能免除开发者自身构成侵权时的责任**（许可协议不能对抗侵权法强制性规定），因此第2条（代码边界）才是根本保障。

---

## 五、边界红线（不可妥协，永远不做）

1. **永不添加**"解析加密流 / 绕过 DRM / 绕过防盗链 / 去版权"类功能 —— 一旦加入即落入《著作权法》53条红线，性质质变；
2. **不为特定侵权场景定向适配**（如定向破解某网站）—— 构成"明知 + 实质性帮助"；
3. **宣传物料禁止诱导侵权**（如"免费下载付费视频"）—— 注意 README、商店描述措辞；
4. **收到版权投诉通知必须及时响应**（下架/处理）—— 否则失去"通知-删除"抗辩，仓库可能被下架甚至封号。
